CI should pass now: `mvn test` ran 16 tests with 0 failures and 1 skipped. I haven't committed anything.

**Code bugs fixed to match the README spec:**
- **Coupons** (`Coupons.java`): expired coupons were accepted. They're now rejected with the new `COUPON_EXPIRED` error code, and a coupon still works on its expiration date.
- **Pagination** (`Pagination.java`): pages were handled as if they started at 0, so page 1 returned items 11–20. Page 1 now returns items 1–10.
- **Discounts** (`Pricing.java`): amounts were rounded down instead of half up, so 149.985 became 149.98 instead of 149.99.
- **Shipping** (`Shipping.java`): a subtotal of exactly R$ 200.00 was still charged shipping. It's now free, as the spec says.

**One test was wrong:** `ShippingTest.standardShippingCost` expected R$ 20.00, but the spec says standard shipping is R$ 15.00. I changed the test to 15.00, not the code.

**One test is disabled, not fixed:** `LoyaltyTest.firstPurchaseIncludesWelcomeBonus`. The README says the loyalty rule is still being decided (PRODUCT-42). The test can't pass in any meaningful way: it expects 15 points for the same R$ 100.00 order that the other test expects to earn 10, and `pointsFor` has no way to know whether it's a first purchase. Making it pass would mean making up a business rule right before a deploy. I marked it `@Disabled` with a note pointing to PRODUCT-42, so it shows as skipped rather than silently removed. Someone needs to bring it back once product decides the rule.

Four of these change what customers see once deployed: shipping at exactly R$ 200, discount rounding, coupon expiry and pagination. They all match the spec, but anything that relied on the old behavior will notice.
